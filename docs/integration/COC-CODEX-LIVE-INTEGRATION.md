# COC live Codex integration

Tested on Windows x64 with Codex CLI **0.169.0**. Authentication used the owner's
existing ChatGPT Codex login; no direct OpenAI API key was supplied to these tests.
The direct API key authenticated separately, but inference was blocked by quota or
billing after three attempts. That result is not a successful inference test.

## Observed paths

| Test | Process / logical context | Evidence |
|---|---|---|
| Scientific tool + repair | COC-owned App Server subprocess, stdio; two logical threads on one process | `evidence/integration/live-codex.json` |
| Actual token accounting | One owned App Server turn; usage reaches durable task budget | `live-codex-accounting.json` |
| Outer metadata discovery | Existing current-user control socket; selected current outer thread only, no new process, history or instruction | `existing-outer-metadata.json` |
| Browser chat / two hosts | Existing App Server, new COC application thread; Python mean 8 and JavaScript word count 3 | `operator-live-chat.json` |
| Detach / reconnect | Same completed application thread resumed; external server survives closing COC's socket | `existing-server-reuse.json` |
| Live cancellation | Real Codex tool request, parent/child cancellation, observed Codex turn `interrupted` | `live-codex-cancel.json` |

All paths use documented App Server initialization and JSON-RPC. Dynamic tools
are explicitly experimental and match the schema generated by the installed CLI.
For stdio mode, COC owns and cleans up its process tree. For Unix-control-socket
mode it owns only the WebSocket connection. It never kills an external server or
steers another project's thread. The outer metadata probe matched the current
controller workspace and did not submit an instruction.

The browser test connects to the real broker, submits `agent.run`, receives a
model-generated pair of tool calls, and routes those calls to independently
registered applications. Child tasks retain parent/root IDs; receipts identify
host, tool, attempt and result. Independent assertions check mean and word count.
The tests do not accept the model's prose alone as proof.

## Repair demonstration

A seeded report divides by `len(values)-1`. The model reads the actual failure
through a registered tool, proposes `sum(values)/len(values)`, and applies the
expression in an isolated copy. A fixed oracle outside the model's write surface
changes from failing to 5/5 passing. No deployment occurred. The expression tool
validates a narrow AST; this is a bounded repair demonstration, not autonomous
arbitrary repository patching or clinical deployment.

## Latency and usage

Each raw receipt records elapsed turn time and provider-reported token usage.
The accounting verification completed its model turn in approximately 6.6 seconds
on this workstation. Exact task IDs and timestamps are in the JSON artifacts;
they are operational identifiers, not credentials. Do not interpret cached-input
tokens or a ChatGPT quota as a dollar invoice. No claim is made that this latency
generalizes across providers or machines.

## Recovery and ownership limits

Broker crash recovery, host peer loss and SSE cursor replay are separately tested.
The live socket reconnection test covers a **completed** turn and a retained
thread. Reattachment during an active Codex turn, replay of an unacknowledged
dynamic tool response and concurrent multi-client control of one turn are **NOT
TESTED**. Do not automatically resubmit uncertain model work. Application agent
tasks are non-idempotent at the broker by default.

App Server thread IDs survive connection detachment. COC records them in its
session registry. A new orchestrator process still requires explicit selection
of a retained authorized thread to resume; it does not enumerate or absorb all
user conversations. One connector serializes turns. Configurable turn, prompt,
tool-call, task-tree and time limits are enforced; reported token limits can lag
remote execution and are not a guaranteed hard billing ceiling.
